## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inventory scanner -> App startup state | Scanner failures and untrusted local observations enter React state before user decisions. |
| App startup state -> Wizard UI | Inventory facts become visible terminal text that can influence setup choices. |
| Existing rc/gitconfig data -> wizard defaults | Local file data is reused for defaults and must not leak secrets or crash rendering. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Denial of Service | `src/app.tsx` startup scan | mitigate | Initialize a fallback report before async scanning, catch scan failures, and convert failures into warning id `inventory-startup-failed`. |
| T-02-09 | Spoofing | `src/steps/inventory.tsx` summary text | mitigate | Render concise inventory evidence and warnings only; avoid final provenance labels reserved by D-02. |
| T-02-10 | Information Disclosure | `src/modes/wizard.tsx` defaults from inventory environment | mitigate | Reuse existing rc/gitconfig filtering behavior and render summary counts rather than raw rc/env content. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install tasks exist in this plan; package legitimacy audit in research lists no new packages. |
</threat_model>
