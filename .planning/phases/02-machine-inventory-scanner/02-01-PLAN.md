**As a** tilde user, **I want to** see known installed-tool facts before choosing setup options, **so that** I can trust what tilde will manage before it changes anything.

<objective>

This plan implements D-01 through D-09 and D-15 through D-17 without adding Phase 4 final provenance labels from D-02.

Purpose: replace the legacy environment-capture boundary with an evidence-backed inventory report that can support later Homebrew classification and provenance work.
Output: new inventory source files, targeted metadata rows for INV-01 categories already represented by tool categories, scanner-owned shell/core-tool facts, wizard startup wiring, and failing-then-passing tests.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External CLI output -> inventory scanner | Homebrew and environment helper output is untrusted machine data parsed into facts. |
| Local filesystem -> inventory scanner | Dotfiles and rc files may contain secret-looking content and must not be resolved or persisted as secrets. |
| Inventory report -> Ink summary | Evidence and warnings become user-facing text and must not overclaim final provenance categories. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `src/inventory/scan.ts` Homebrew matching | mitigate | Use `listInstalledFormulae()` and `listInstalledCasks()` helper results as arrays; do not concatenate package names into shell strings. |
| T-02-02 | Information Disclosure | `src/inventory/scan.ts` rc/env capture compatibility | mitigate | Keep rc/gitconfig data inside `environment`, preserve existing secret exclusion behavior, and do not resolve backend secret references. |
| T-02-03 | Spoofing | `src/inventory/summary.ts` labels | mitigate | Render evidence/count labels only; do not emit tilde-managed, manual, OS-provided, or final unknown provenance labels in Phase 2 per D-02. |
| T-02-04 | Denial of Service | `src/app.tsx` startup scan | mitigate | Initialize a fallback report before async scanning, catch scan failures, and convert failures into `InventoryWarning` data so the wizard still renders. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install tasks exist in this plan; package legitimacy audit in research lists no new packages. |
</threat_model>
