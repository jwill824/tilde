<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Homebrew CLI output -> package-manager helpers | Command stdout is untrusted and parsed as newline-delimited data. |
| Package-manager helpers -> inventory classifier | Installed package names and request-state lists become user-visible counts. |
| Inventory report -> summary helpers | Request-status counts can influence user trust before apply decisions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Tampering | `listInstalledOnRequestFormulae()` | mitigate | Call `runBrew()` with the exact argument array `['list', '--installed-on-request', '--formula', '--full-name']`; never interpolate package names into shell strings. |
| T-02-12 | Spoofing | `summarizeInventory()` Homebrew labels | mitigate | Render request-status counts and warnings only; avoid final managed/manual/OS-provided labels reserved by D-02. |
| T-02-13 | Denial of Service | `scanInventory()` request-state lookup | mitigate | Catch installed-on-request failures independently, keep installed package data, and emit warning id `homebrew-request-state-unavailable`. |
| T-02-14 | Information Disclosure | Homebrew audit data | accept | Formula and cask names are local package identifiers; default summary renders counts, while unmatched detail remains structured report data. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install tasks exist in this plan; package legitimacy audit in research lists no new packages. |
</threat_model>
