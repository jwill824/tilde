<objective>
Close the user-visible trust gaps where startup inventory can appear complete before scanning finishes and where installed metadata ids can become package-manager install defaults. This implements D-03, D-07, D-15, D-17, D-18, INV-01, INV-03, and INV-04 for the gap closure.

Purpose: users must either see completed inventory facts or an explicit failed-scan warning before choosing setup/apply actions, and inventory facts must not write unsafe generic tools into `config.tools`.
Output: shared inventory readiness state, blocked loading UI, explicit failed fallback rendering, and integration coverage for async scan behavior plus safe tool defaults.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Startup scanner -> App state | Async scanner completion controls whether setup/apply choices can be shown. |
| Inventory report -> wizard setup steps | Inventory facts inform trust summaries but must not become install defaults without explicit mapping. |
| Inventory report -> config-first confirmation | Inventory readiness gates apply choices before local system changes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-18 | Spoofing | `InventoryStep` headings | mitigate | Show `Inventory scan complete` only for `ready` and `Inventory scan failed` only for explicit failed fallback state. |
| T-02-19 | Tampering | `Wizard` -> `ToolsStep.defaultTools` | mitigate | Remove broad inventory metadata id flow into generic package install input; preserve only user-entered or checkpoint-restored tools. |
| T-02-20 | Denial of Service | pending `scanInventory()` | mitigate | Render loading state without crashing and without exposing setup/apply choices until ready or failed. |
| T-02-21 | Information Disclosure | inventory summaries | mitigate | Continue using `summarizeInventory()` aggregate lines and warnings; do not dump rc/env contents or unmatched Homebrew audit names. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install tasks exist in this plan; package legitimacy audit in research lists no new packages. |
</threat_model>
