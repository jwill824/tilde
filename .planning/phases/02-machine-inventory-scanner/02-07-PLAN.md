## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Homebrew helper outcome -> metadata fact | Successful helper calls prove command availability and influence package-manager installed state. |
| Homebrew helper failures -> metadata fact | Failures become warning-backed unknown state rather than crashing or overclaiming installation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-22 | Spoofing | `homebrew` package-manager fact | mitigate | Mark installed only when a Homebrew helper resolves; failed helpers produce unknown state with warning-backed evidence. |
| T-02-23 | Tampering | Homebrew command evidence | mitigate | Use existing helper results from `src/utils/package-manager.ts`; do not execute new shell strings or parse arbitrary user input. |
| T-02-24 | Repudiation | scanner warning evidence | mitigate | Attach the first Homebrew warning id to inconclusive `homebrew` evidence when availability cannot be confirmed. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install tasks exist in this plan; package legitimacy audit in research lists no new packages. |
</threat_model>
