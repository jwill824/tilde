## Phase Goal

**As a** tilde developer, **I want to** maintain wizard tool metadata in one shared registry, **so that** current steps can consume canonical tool facts without user-visible behavior changes.

<objective>
Create the first working registry slice for browser metadata plus a real non-plugin note-taking catalog.

Purpose: This establishes the shared metadata boundary required by META-01, META-02, META-04, and META-05 while honoring D-01 through D-06 and D-08 through D-14. The slice is static and pure: it does not broaden PluginRegistry, it does not execute Homebrew/defaultbrowser commands, and it does not introduce new packages. It includes browser metadata for the migration path and the note-taking catalog from `src/steps/tools.tsx` to satisfy D-03 with an actual non-plugin family.
Output: `src/tools/metadata.ts`, `src/tools/registry.ts`, `src/tools/note-taking-metadata.ts`, `src/plugins/first-party/browser/metadata.ts`, and `tests/unit/tool-metadata.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Static metadata -> registry helpers | Developer-authored metadata becomes source data for later wizard, scanner, dotfile, and provenance behavior. |
| Registry helpers -> future command consumers | Install identifiers may later be passed to package-manager wrappers, so malformed values must be rejected early. |
| Non-plugin catalog -> shared registry | Note-taking metadata is not backed by `TildePlugin`, so registry validation must not rely on plugin instances. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `ToolMetadataSchema`, `validateToolMetadata` | mitigate | Validate required `id`, `label`, `category`, `supportedPlatforms`, strict-but-compatible Homebrew id shape, path arrays, and control-character-free labels; cover browser and note-taking metadata with `tests/unit/tool-metadata.test.ts` from `01-VALIDATION.md`. |
| T-01-01B | Information Disclosure | `configPaths`, `dotfilePaths`, `externalIds` | mitigate | Keep fields as static paths and external identifiers only; do not resolve env vars or persist raw secrets. Tests must include a malformed secret-looking fixture if schema rules add a secret guard. |
| T-01-SC | Tampering | package installs | accept | Phase 1 adds no npm/pip/cargo install task and RESEARCH.md Package Legitimacy Audit says no new package install is recommended. |
</threat_model>
